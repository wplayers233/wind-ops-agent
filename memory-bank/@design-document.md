# 设计文档真源（@design-document.md）

> 内部真源：产品定义、主线与验收标准。用户侧功能说明见 `README.md`。

## 1. 产品定义

面向风电设备运维的多模态 RAG 工作台（本地可复现 Demo）。系统将报警码、设备现象、PDF/PPT 资料和图解证据组织为可追溯的诊断结果，支持混合检索、安全确认、会话记忆和质量评估。

## 2. 用户与场景

风电运维/技术支持工程师：遇到设备故障 → 输入报警码或现象描述 → 系统返回候选原因、排查步骤、工具/备件建议、风险提示，每条结论带可追溯证据引用；高风险操作（停机、断电、挂牌）必须经用户确认后才继续。

## 3. 主线（唯一主线）

导入多模态资料 → 提问 → 意图识别 → 混合检索（BM25 + dense + RRF，可选重排）→ 安全评估（高风险中断确认）→ 诊断 → 答案组装 → 会话/长期记忆写回 → 质量评估。

## 4. 第一闭环（离线闭环）

不配置任何外部服务即可端到端跑通：`/ingest`（本地解析 + Mock provider）→ `/chat`（规则意图 + 本地索引检索 + 安全门）→ `/retrieve`（可解释证据）→ `/evaluation`(离线黄金集)。这是验收的最低标准：任何改动不得破坏离线闭环。

## 5. 非目标（non-goal）

- 生产部署、多租户、云运维、SLA。
- 真实风机设备接入、实时遥测数据。
- 高并发、横向扩展。
- 未配置外部服务时伪造"已接入"状态。

## 6. 验收标准

1. `./build.ps1` 通过（后端门禁 + 前端生产构建）。
2. 离线闭环可用：`/ingest`、`/chat`、`/retrieve`、`/evaluation` 无外部依赖可调用。
3. 证据可追溯：每条答案带引用与检索得分。
4. 安全门生效：高风险操作中断并等待确认（见 `tests/unit/services/test_safety.py`）。
5. 降级可观测：provider 状态、评估 fallback 原因在响应中可见。
